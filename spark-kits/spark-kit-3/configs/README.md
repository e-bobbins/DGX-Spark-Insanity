# Configuration Standards

This directory contains configuration templates and documentation for the DGX Spark LLM Stack.

## Configuration Hierarchy

The DGX Spark LLM Stack uses a **single source of truth** model:

```
┌─────────────────────────────────────────────┐
│              inventory.yaml                  │
│         (EDIT THIS_FILE ONLY)                │
└─────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────┐
│           deploy.sh (generates)              │
└─────────────────────────────────────────────┘
                        │
        ┌───────────────┴───────────────┐
        ▼                               ▼
┌────────────---┐             ┌───────────────┐
│ generated/    │             │ Docker       │
│ - litellm-    │             │ compose     │
│   config.yaml │             │ (running)    │
│ - workers/    │             │ - containers │
└────────────---┘             └───────────────┘
        │                               │
        ▼                               ▼
┌─────────────────────────────────────────────┐
│              Live Deployment                 │
└─────────────────────────────────────────────┘
```

## What Can Be Hand-Edited

| File | Can Edit? | Notes |
|------|-----------|-------|
| `inventory.yaml` | ✅ **Yes** | Single source of truth |
| `recipes/*.yaml` | ✅ **Yes** | Per-model configuration |
| `.gitignore` | ✅ **Yes** | Git ignore patterns |
| `generated/*` | ❌ **No** | Generated by deploy.sh |
| `secrets/*` | ❌ **No** | Generated by deploy.sh |
| `docker-compose.hub.yml` | ⚠️ **Caution** | Template used by deploy.sh |

## Configuration Files Reference

### inventory.yaml

The **primary configuration file**. Defines:

```yaml
lab:
  client_subnets: ["10.0.0.0/24", "192.168.1.0/24"]
  nfs:
    enabled: true
    export_path: "/mnt/shared-models"

nodes:
  - node_id: spark-01
    role: hub+worker
    lan_ip: "10.0.0.30"
    model_recipe: "qwen3.6-35b-a3b-nvfp4"

recipes:
  qwen3.6-35b-a3b-nvfp4:
    model_name: "nvidia/Qwen3.6-35B-A3B-NVFP4"
    served_model_name: "qwen3.6-35b-a3b-nvfp4"
    tool_call_parser: "qwen3_xml"
    reasoning_parser: "qwen3"
    max_model_len: 262144
    gpu_memory_utilization: 0.8
    max_num_seqs: 15
```

### docker-compose.hub.yml

Template for the hub stack. Used by deploy.sh to start LiteLLM and Postgres.

**Do not edit this file unless you understand Docker Compose thoroughly.**

### recipes/*.yaml

Per-model serving configuration. Add new files here for new models.

## Network Configuration

### Firewall Rules

All firewall rules are auto-configured by deploy.sh based on inventory.yaml:

- **Hub**: Port 4000 open from client subnets only
- **Worker**: Port 8000 open from hub IP only
- **All**: SSH open, outgoing traffic allowed

### Docker Network

- Name: `spark-kit-llm-net`
- Type: Bridge network
- Postgres: Internal only (bridge network)
- LiteLLM: Port 4000 published to host IP
- vLLM: Port 8000 published to host IP

## Security Configuration

### Service User

- Name: `llm-svc`
- Created by: deploy.sh (with sudo)
- Used by: All containers (--user SVC_UID:SVC_GID)

### Secrets

All secrets are in `secrets/` directory (gitignored):

- `db_password.txt` - PostgreSQL password
- `litellm_master_key.txt` - LiteLLM master key (sk- prefixed)
- `vllm_api_key.txt` - vLLM API key for this node

## Performance Configuration

### vLLM Settings (from recipe)

- `gpu_memory_utilization: 0.8` - 80% of 128GB = ~102GB
- `max_num_seqs: 15` - Maximum concurrent sequences
- `max_model_len: 262144` - 256K token context window

### Container Resources

- CPU: Unlimited (container can use all available)
- Memory: Unlimited (OS manages)
- GPU: All available GPUs (--gpus all)
